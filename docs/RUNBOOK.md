# Работа и обслуживание PremierLift CRM

Актуально: 5 сентября 2026. Локальный запуск и роли описаны в [README](../README.md). Эта инструкция относится к текущему интерфейсу.

## Ежедневная работа диспетчера

1. На «Обзоре» проверьте неназначенные, аварийные и просроченные заявки. Нажатие счётчика открывает соответствующую выборку. «Выполнено сегодня» считается по времени завершения в Алматы.
2. «Новая заявка» открывает форму. Выберите существующий лифт через поиск по адресу/серийному номеру; объект и координаты подтянутся. Для обращения без конкретного лифта выберите объект в дополнительных полях или заполните адрес вручную. Укажите описание, тип поломки и приоритет.
3. После создания откройте карточку заявки. В ней есть адрес, исполнитель, сроки, связи с объектом/лифтом, комментарии и вложения. Связанные активные обращения помогают заметить дубли. Изменение описания, типа, приоритета и SLA, назначение мастера, отмена и архивирование выполняются здесь.
4. «Доска работ» показывает этапы. В таблице «Заявки» доступны поиск, даты, статусы, приоритет, мастер и сроки. Поиск по всей CRM в верхней панели открывает объект, лифт, заявку, клиента или договор.
5. «Отчёты» использует **дату создания** и выбранный период включительно, время Алматы. Средние сроки считаются от создания, реакция — до прибытия. Отменённые обращения не входят в рейтинг повторных неисправностей. Архивная история входит в отчёт.

Если сохранение прервалось, поля формы остаются. Сначала обновите реестр и проверьте, появилась ли запись, затем повторите при необходимости.

## Объекты, лифты, клиенты и договоры

«Объекты → Добавить объект»: название, адрес, координаты, контакты, клиент и договор. Договор должен соответствовать клиенту. Объект можно сделать неактивным, сохранив историю. В карточке доступны список лифтов, активные/последние заявки и переход на карту.

«Лифты → Добавить лифт»: выберите объект, заполните серийный номер, метку и подъезд. Адрес, координаты и связи наследуются от объекта. При изменении адреса объекта обновляются текущие данные лифтов; адрес уже созданной заявки остаётся историческим снимком. Карточка лифта содержит сведения, обслуживание, активные/последние заявки и подробную историю. Сигнал повторных обращений: три неотменённых или две срочные заявки за 30 дней.

Клиенты и договоры находятся в отдельном разделе. Договор связывается с клиентом, хранит номер, срок, статус и справочные SLA. Счета, платежи и автоматическое применение договорного SLA не реализованы.

## Импорт лифтов

Перед импортом остановите приложение и сделайте резервную копию. Реестр принимает CSV UTF-8 и первый лист XLSX с заголовками. Файл обрабатывается в памяти, результат показывает созданные, пропущенные и некорректные строки.

```csv
address,entrance,lift_label,serial_no,lat,lon,status
"Алматы, Абая 10",1,Лифт A,SN-001,43.238949,76.889709,ACTIVE
"Алматы, Толе би 5",2,Лифт B,SN-002,,,ACTIVE
```

Адрес обязателен. Поддерживаются русские aliases «адрес», «подъезд», «лифт», «серийный номер», «широта», «долгота», «статус». Координаты — конечные числа в диапазонах широты ±90 и долготы ±180; дробная запятая допустима. Статус — ACTIVE/INACTIVE.

Дубли проверяются по серийному номеру, а без него — по полному сочетанию адрес + подъезд + метка. Импорт пропускает существующие лифты, не обновляет их. Объекты группируются по адресу и связям. Клиенты/договоры не создаются из файла. После импорта проверьте ошибки строк, реестр и «Карту объектов», затем выгрузите CSV/XLSX для сверки.

## Мастера и обслуживание

В «Мастерах» видны активность и текущая нагрузка. Автоназначение выбирает активного сотрудника с минимальным количеством открытых заявок; при равенстве — меньший id. Ручное назначение доступно в карточке заявки. При деактивации сотрудника открытые заявки перераспределяются; операция без замены блокируется.

Администратор управляет пользователями, ролями, временными паролями и связанными профилями в «Пользователи и допуск». Отключение доступа и деактивация профиля мастера — разные операции.

«Обслуживание» хранит планы ТО лифтов, периодичность и следующую дату. Из плана можно создать связанную заявку. Сводка лифта показывает его планы. Показатель ТО на обзоре считает активные планы, срок которых наступил, и все планы с явно заданным статусом «Просрочено».

## Мобильная смена

1. Войдите мастером онлайн и откройте `/mobile`. Дождитесь загрузки своих заявок и статуса «Синхронизировано».
2. Примите назначенную заявку. На объекте нажмите «В работу», разрешив геолокацию. Сервер принимает переход, если расстояние не превышает 500 м. Координаты объекта должен заполнить диспетчер.
3. Добавляйте комментарии и фото. Для ожидания укажите причину; для завершения выберите причину закрытия, при необходимости итоговый комментарий.
4. Без сети действия и фото остаются в очереди, локальный статус меняется сразу. Можно перезагрузить приложение. История лифта доступна без сети после её предварительной загрузки; просмотр уже отправленных фото требует связи.
5. При возвращении сети открытое приложение синхронизируется. «Обновить» запускает повторную проверку вручную. Повторная отправка тех же действий/фото не создаёт дублей.
6. «История» показывает завершённые работы мастера. «Настройки» содержит установку, выход и сброс локальных данных.

Ограничения фото: до 8 МБ на файл, до 20 неотправленных фото на устройстве. Для GPS и установки на телефоне нужен HTTPS; localhost является исключением только на самом компьютере. Фоновая отправка при закрытом приложении не гарантируется.

### Ошибки очереди

- Временная ошибка сети: дождитесь связи и нажмите «Обновить».
- Ошибка сервера или загрузки фото: «Требует внимания → Повторить».
- Конфликт версии: заявка уже изменена на сервере. Уточните состояние у диспетчера. «Удалить из очереди» с подтверждением удаляет ошибочное событие и следующие зависимые изменения этой заявки, затем восстанавливает состояние сервера. После этого выполните нужное действие заново. Фото сохраняются отдельно.
- Вне геозоны/нет координат: исправьте причину, удалите ошибочную цепочку и заново нажмите «В работу», чтобы получить актуальные координаты.
- Чужое назначение/архив/закрытие: локальное действие не применяется. Не повторяйте его без проверки актуального статуса.
- Истекла сессия или вошёл другой пользователь: очередь сохраняется, синхронизация блокируется до входа в свой аккаунт.

Кеш и очередь разделены по пользователям. Выход сохраняет личную очередь для следующего входа в тот же аккаунт. «Сброс офлайн-данных» удаляет локальную очередь и требует подтверждения с количеством записей.

## Backup и восстановление

Остановите все процессы приложения до копирования БД и файлов:

```bash
venv/bin/python scripts/backup_local.py
```

В `backups/<UTC-время>/` сохраняются `lift_crm.db`, `uploads/`, архивы/экспорты и `manifest.json`. Отсутствующие необязательные файлы отмечаются предупреждениями. Держите дополнительную копию вне рабочего компьютера.

Восстановление сначала проверьте в отдельном каталоге:

```bash
venv/bin/python scripts/restore_local.py backups/<имя-копии> --root /tmp/liftcrm-restore-check
```

Для замены рабочих данных сервер должен быть остановлен; сначала сохраните нынешнее состояние. `--force` явно разрешает перезапись и замену каталога вложений:

```bash
venv/bin/python scripts/restore_local.py backups/<имя-копии> --force
```

Перезапустите приложение и проверьте вход, заявки, вложения, реестр и архив. Не удаляйте базу как способ устранения блокировки SQLite: сначала найдите лишний процесс, дождитесь окончания записи и проверьте резервную копию.

## Настройки сервера

Переменные задаются в окружении процесса; `.env.example` не загружается автоматически.

- `HOST=127.0.0.1`, `PORT=5000`, `DEBUG=false` — локальные значения по умолчанию. Внешний интерфейс задаётся явно. Для эксплуатации используйте WSGI-сервер за HTTPS reverse proxy вместо встроенного Flask server.
- `APP_ENV=production` требует `SECRET_KEY` не короче 32 символов, отличающийся от тестового; включает Secure cookie по умолчанию. Локальный HTTP запускайте в development.
- `ADMIN_USERNAME/ADMIN_PASSWORD`, `DISPATCHER_USERNAME/DISPATCHER_PASSWORD` — начальные пользователи новой БД, не команда смены существующих паролей.
- `SESSION_COOKIE_HTTPONLY`, `SESSION_COOKIE_SAMESITE`, `SESSION_COOKIE_SECURE` — параметры cookie. Изменяющие запросы проходят origin-проверку.
- `CORS_ALLOWED_ORIGINS` — явный список при необходимости, wildcard с cookie запрещён.
- `TRUST_PROXY_HEADERS=true` и `PROXY_FIX_X_FOR` — только за доверенным прокси при закрытом прямом доступе.
- `SLA_RESPONSE_MINUTES=30`, `SLA_COMPLETION_MINUTES=120` — базовые сроки. Для аварийной заявки при создании по умолчанию 5/60 минут, высокой — 15/90, если нет ручных значений.
- `SMTP_SERVER/PORT/USERNAME/PASSWORD` — необязательная отправка отчёта по завершению; без конфигурации отправка пропускается.

`GET /api/health` проверяет доступность. Ошибки и операции пишутся в журнал процесса, бизнес-изменения — также в audit. Лимит входа: 10 попыток за 10 минут на IP+логин, хранится в памяти процесса. Ошибки API возвращаются JSON с сообщением.

## Проверка обновления

```bash
venv/bin/python -m pytest -q
node --test tests/*.test.cjs
npm run build:css
```

Браузерный сценарий: объект → лифт → заявка → комментарий → поиск → отчёт; затем мастер → принять offline → перезагрузить → online → пустая очередь, одно применение на сервере. Дополнительно проверьте геолокацию, ожидание/завершение, фото и смену аккаунта. Для демонстрации используйте `scripts/preview_crm.py`, который не открывает рабочую базу.

После изменения мобильного JS/CSS/оболочки увеличьте `CACHE_NAME` в `static/sw.js`. Первый вход и обновление ресурсов требуют связи. Реальную камеру/GPS и установку на конкретном телефоне проверяйте на HTTPS-адресе сервера.
